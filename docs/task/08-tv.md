## TV-1 — 替换TV连接向导与运行状态

- 优先级：**P1**；前置：`CFG-2`、`NET-1`；初始状态：**待开发**
- 来源定位：[§9 双端交互](../design/wled-direct-ambilight-feasibility.md#ui)；[§3 配置契约](../design/wled-direct-ambilight-feasibility.md#config)；[§8 设备控制与LAN安全](../design/wled-direct-ambilight-feasibility.md#network)；[E10](../design/wled-direct-ambilight-feasibility.md#e10)。

### 1. 交付物

- 在现有Leanback引导中提供NSD/有限扫描/手动Host、HTTP/UDP端口、能力确认、版本/count/通道提示。
- MainActivity呈现采集、正在发送、设备观察过期、关灯未确认等不同状态；移除旧Host/Port/Priority测试含义。

### 2. 关键约束（含 DRY）

- DRY：复用CFG字段描述/校验、NET ProbeResult与CAP状态模型；SettingsStepBaseFragment继续承担主题/导航公共部分。
- 不在GuidedStep中做网络或保存半套配置；发现结果用身份/时间更新，不能仅缓存IP。
- 本卡可用fake probe先独立验收，真实运行状态集成在TV-2完成。

### 3. 独立测试与验收

**独立测试**（完成后勾选并附命令/原始证据）：

- [x] TvSetupTest模拟发现成功/超时/空结果/能力冲突，验证manual入口始终可到达。
- [x] 输入非法count/端口时显示与mobile相同错误码，不保存部分字段。
- [ ] 所有向导步骤D-pad进入、返回、取消，页面销毁后迟到扫描不更新UI。

**验证入口**：`TV仪器测试 TvSetupTest；公共校验以CFG/NET单测为前置`。Gradle入口在FND基座完成后执行；仪器/硬件测试必须记录设备与退出码，不能由JVM通过推定。

**验收标准（量化）**：

- 发现/手动两条路径各完整走通；错误输入提交数0。
- 主线程网络0；焦点陷阱0；不显示旧后端或UDP已确认连接误导文案。

**证据（2026-11-16，本地部分）**：`WledSetupController`与`WledConnectionStepFragment`提供手动路径；`WledScannerTask`仅在当前私有IPv4 /24枚举≤256候选、4并发、15秒、可取消；`WledNsdDiscovery`浏览`_wled._tcp.`并解析候选；`ScanResultActivity`经`SettingsDraftController`保存WLED host/HTTP/UDP/DDP/count/通道，MainActivity状态文案区分发送/停止且不宣称逐帧确认。4个`TvSetupTest`+6个`WledDiscoveryTest`通过。D-pad全流程、真机仪器与API矩阵未执行，TV-1保持“待验证”。**2026-11-17 迟到扫描修复**：`NetworkScanActivity` 的 `onScanStarted/onScanFinished/onScanError` 与 Nsd 探测结果统一增加 `isFinishing()/isDestroyed()` 守卫，页面销毁后的迟到结果不再触碰视图树；自动化回归因同时段重构暂未纳入。证据见`docs/verification/wled/tv-1/`。

**证据（2026-11-16，本地部分）**：`WledSetupController`与`WledConnectionStepFragment`落地；4个`TvSetupTest`通过，覆盖手动输入、probe成功/失败、非法端口与mobile同错误码、整份保存不落半套。TV手动步骤已接入共享ConfigRepository/Validator，probe在后台worker执行，GuidedStep不做网络/半套保存。NSD/有限扫描、ScanResultActivity、MainActivity运行状态与D-pad/仪器测试未完成，TV-1保持“待验证”。证据见`docs/verification/wled/tv-1/`。

## TV-2 — 完整布局设置、预览与首套预设

### 1. 交付物

- 实现Basic/Advanced全部布局参数、RGBW white mode、平均色、帧率/分辨率及停止提示；挂接TV预览宿主。
