# 配置与排障手册

> 参数、协议与兼容要求的唯一规范是[技术架构](../design/architecture.md)。本文只说明如何配置、验证与排查。

## 1. 首次配置

1. 确认手机/TV 与 WLED 控制器在同一可信 LAN。
2. 在 WLED Connection 页填写 host/IP，或使用 NSD 发现/本地扫描。扫描由用户触发，只覆盖当前本地网段。
3. 分别确认三个端口：
   - HTTP 端口（默认 80）：探测、状态读回与开关控制。
   - UDP realtime 端口（默认 21324）：DNRGB/DRGB 输出。
   - DDP 端口（固定 4048）：RGBW 输出，也可用于 RGB。
4. 选择协议：`auto` 让 RGB 按灯数选择 DRGB/DNRGB、RGBW 使用 DDP；也可显式选择 `dnrgb` 或 `ddp`。RGBW 不允许 DNRGB。
5. 确认硬件通道格式（RGB 或 RGBW）与物理灯数。探测只提出建议，必须由用户确认；物理灯数必须与设备观察 `count` 一致，不一致时不能启动。
6. 保存后设置标记为“下次启动生效”，运行中的会话不会被热更新。

## 2. 布局参数

| 参数 | 说明 |
|---|---|
| Top/Bottom/Left/Right | 每边灯数，0..1000；逻辑槽位顺时针排列，不额外增加四角灯 |
| Physical LED count | 设备全部可寻址灯数 M；尾灯与 BLACK gap 每帧输出黑色 |
| Gap length / position | 缺口长度与起点；SKIP 表示该区间物理灯缺失，BLACK 表示灯珠存在但需熄灭 |
| Input | 逻辑环起点，按 `floorMod(input, K)` 归一化 |
| Reverse | 反转物理槽位顺序；Input 在反转时不是直观物理 0 对应的原始槽号 |
| H/V Depth | 顶底/左右采样带深度，1..100% |
| Overlap | 切向归一化绝对扩展，0..100%；10% 表示两侧各扩展屏幕宽/高的 10% |
| Edge Gap | 沿边端点内缩，0..50% |
| 四角坐标 | TL/TR/BR/BL 各自的水平/垂直百分比 |
| 帧率 | 1..60，默认 30；首套验收显式选择 60 |
| 采集长边 | 1..640 px，默认 640；不放大源画面 |
| 平均色 | 默认关闭；开启后整域平均仍执行 Gap/尾黑 |

几何必须满足：四角凸、无自交、面积非零，上/下边 x 递增、左/右边 y 递增。非法草稿不会保存为活动配置。

### 2.1 首套 274 预设

- Top=86、Bottom=90、Left=49、Right=49、Gap=0、Input=161、Reverse=true
- H Depth=8%、V Depth=5%、Overlap=0、Edge Gap=0
- 四角：TL(0,0)、TR(100,0)、BR(100,100)、BL(0,100)
- 物理映射：`slot(p)=floorMod(160-p,274)`；物理 0/25/26/160/161/273 → 逻辑 160/135/134/0/273/161

物理数量必须与 WLED 观察 count 一致；不足时阻断启动，不截断尾灯。

### 2.2 TV 遥控校准：找一对跨角的灯

先配置 WLED，在启动确认页核实并保存设备的寻址条件，然后填写并核实四边灯数。四边均有灯且没有缺口时，可在 TV 布局编辑器进入遥控校准；其他布局继续使用下方的逐边校验。先保存或放弃编辑器里未提交的修改，运行中的采集不会被向导代停。

面向电视，用遥控器移动光点，找到分属相邻两边的连续两颗灯。第一颗物理灯可以在边的中段，不需要猜它在哪个角。例如首套安装的物理 25 在底、26 在右，候选应为 `Input=161 / Reverse=true`。核对四条**整边和两端**后才保存；没有看到亮灯或长度不对时返回重试，而不是猜一个答案。取消不改变原接线配置。退出时“设备关闭未确认”表示没有取得完整关灯回读，并非配置保存失败。

### 2.3 TV 观影场景

打开 **WLED Grabber** 主应用（不是「WLED Grabber（开关）」）。在主页的电源或齿轮图标上按遥控器 **↓**，再按 **确定** 打开「观影场景」，可选「自定义」「影院」「游戏」或「夜间」。入口在两个图标下方，不在齿轮设置里。未运行时只记住下次选择，不会启动采集；运行中切换只改变本机输出颜色，不改布局、帧率或 WLED 全局亮度。「自定义」恢复本次采集启动时的手动质量设置。「夜间」的 25% 是**发送通道值的增益**，不是实测照度。没有首帧时需要等待画面，不能把“已选择”当成灯带已变色。这不是覆盖第三方播放器的全局快捷键。

## 3. 接线验证

1. 打开共用预览，确认四边采样矩形、物理索引/侧别、Gap 与尾灯位置。
2. 使用布局页的逐边/输入位置点亮校验：点一次对应方向保持白色常亮，再次点击同一项熄灭；点其他方向会替换当前方向。输入位置只点亮物理 0 的第一颗灯珠，其余灯黑。离开布局页、修改草稿或打开预览/测试图案会释放校验；采集运行中不抢占输出，需先停止采集。
3. 使用三种测试图案确认实际接线：

| 图案 | 期望 |
|---|---|
| 四边色 | Top 红、Right 绿、Bottom 蓝、Left 白 |
| 行走像素 | 按物理索引递增，BLACK 与尾灯保持不亮 |
| 整带纯色 | 有效灯循环红/绿/蓝/白，Gap/尾灯仍黑 |

统一测试默认 10 秒。大型灯带在 10 秒内可能走不完全带，可从指定索引继续验证，不能据此宣称全带通过。

## 4. RGBW 前提

- RGBW 使用 **DDP**；DNRGB 不得承载 RGBW，也不使用 type5。
- WLED 的 auto-white 必须为 **Manual**，全局 override 不得改回自动；否则 `(0,0,0,255)` 可能被重算成全黑。
- 选择 `min_subtract` 或 `preserve` 后，用白色图案确认。`preserve` 保留 RGB 并叠加 W，不保证亮度/色度恒定。
- 没有 RGBW 样机时不得声称已验证。首套 WS2815 是 RGB，不能当作 RGBW 验收。

## 5. 排障

### 5.1 发现/连接失败

1. 确认设备在同一可信 LAN；可手动输入 host/IP。
2. 检查 HTTP 端口（默认 80）、UDP realtime 端口（默认 21324）与 DDP 4048 是否独立配置且未被占用。
3. 探测超时/拒绝/响应体超限时界面显示明确原因；UDP 写出成功不代表设备可达。
4. 确认 WLED realtime offset=0、DMX 起始地址=1、main-segment-only 关闭，且没有额外 LED map 或总线反向；否则逐灯寻址会错位。
5. 设备身份（MAC/版本/count）变化后需重新确认，不沿用先前 IP 的缓存能力。

### 5.2 电视待机后灯带闪亮，或显示关灯未确认

- 停止流程：停止新帧 → 清 pending → 等 inFlight → 同一 writer 发黑 → HTTP `on:false/live:false/tt:0` → 读回。
- 只有 `/json/state` 读回 `on=false` 且 `/json/info` 读回 `live=false` 才显示 `CONFIRMED`；超时/断网/身份变化显示 `UNCONFIRMED`。
- 进程被杀时不保证释放；设备有限 realtime timeout 可能恢复原效果。迟到 UDP、其他控制器或 WLED Sync 仍可能重新点亮。
- 不要在未确认时自动把 off 请求重放到下一个会话。

先区分两种情况：**亮屏但画面不动**时应保持最后一次采样颜色；**按遥控器进入系统待机**时应结束本次采集，回到桌面后需重新开始。黑色视频、HDMI 无信号画面与 Android 已进入待机不是同一个信号。排查时记录按键时刻、Android 是否进入睡眠、服务是否记录 `capture stopping: display asleep`（或投屏撤销），再对照同一时间的 WLED `on` / `live` 和肉眼灯光。若电视是直接断电，应用可能根本没有机会发关灯请求；如果已确认关闭后又亮，检查 WLED 预设、其他发送端、Sync 以及控制器是否重启。参见[缺陷与硬件验收步骤](../fixes/2026-11-18-tv-standby.md)。

### 5.3 RGBW 变黑

1. 确认 WLED auto-white=Manual 且 override 未被改回自动。
2. 确认使用 DDP，而非 DNRGB/type5。
3. 用白色测试图案检查 W 通道；仍异常时记录固件版本、灯带类型与 WLED 设置，按未验证处理。

### 5.4 通知与授权

- API33+ 通知权限被拒时不崩溃，但前台通知不可见；下次前台提示。
- 投屏授权被撤销/会话失效后显示 `NEEDS_CONSENT`，不自动重启已终止的授权。
- 开机默认只发用户可见提醒；仅 API 29 且录屏/后台/电池授权与配置齐全时经 `BootActivity` 申请授权，且授权前会再做一次实时探测并匹配已保存的设备确认（首次需先在启动页完成一次确认），未通过则保留提醒、不请求授权；其余情况不后台强拉 Activity。提醒打开共享 `StartCaptureActivity`。
- 受控自启需要：已完成首次设置、`PROJECT_MEDIA=allow`、后台启动能力（悬浮窗或 device owner）、两个后台 AppOps allow、电池优化白名单。管理员 ADB 命令在设置页只复制、不执行。

### 5.5 设备授权状态

检查当前 AppOps：

```sh
adb shell cmd appops get --user 0 com.abrenoch.wledgrabber PROJECT_MEDIA
```

仅对指定用户与包设置；撤销使用同一命令改为 `default`。这是设备侧设置，不随卸载、重置或升级自动保持。

`PROJECT_MEDIA allow` 后，同一 app id/签名的后续采集不再弹出“敏感信息采集”授权；卸载重装或清除应用数据会重置该 AppOp，需要重新授予。启动页的“管理员 ADB 设置”会生成完整命令（含后台/悬浮窗/电池白名单）。

### 5.6 静态画面

静态菜单、暂停视频等画面不会持续产生新帧，灯带保持最后颜色，不会因此自动熄灭；需要关灯时使用停止采集。若灯带在静态画面期间闪烁，先检查 WLED 的 Wi‑Fi 信号与实时超时，而不是画面输入。

## 6. 隐私与安全边界

- 应用只发送逐灯颜色，不保存/上传屏幕图像；不申请麦克风/音频。
- LAN HTTP 为明文且无认证；可信局域网内的其他控制器仍可能控制 WLED。
- 不承诺 DRM/受保护内容可采集；FLAG_SECURE 内容不被绕过。
- 进程被杀时不保证关灯；无法确认设备状态时显示 `UNCONFIRMED`。

## 8. APK 与安装

- applicationId 为 `com.abrenoch.wledgrabber`，仅侧载安装。
- mobile/tv 同 ID，输出的是**替代 APK**，彼此不能共装。
- 当前版本（versionName / versionCode）：TV 为 `2.0 / 2026`，mobile 为 `1.0 / 1012`。Debug 包用于测试侧载；Release 包默认未签名，不能直接安装。
- 电视端：在设置根页选择菜单最后一项 **关于**，可查看项目简介、作者和当前安装包的版本名与版本号。按遥控器返回键即可回到设置，不会保存或丢弃尚未提交的修改。
- 安装步骤：构建对应变体 → 侧载安装 → 完成首次设置 → 预览/测试图案确认接线。
- 同一时间只能有一个发送者控制灯带。

## 9. 不得使用的表述

未验证项包括：物理 60fps 与端到端时延、RGBW 样机、500/1000/2000 灯配置、完整 API 矩阵、签名与发布。禁止表述：“已全部完成”“保证关灯”“支持所有 WLED 版本”“RGBW 已验证”“60fps 已达标”。
