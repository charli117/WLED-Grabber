# 电视待机后灯带闪亮：缺陷与验证（2026-11-18 发起，2026-11-19 本地复验）

**现象边界：** 电视遥控器待机与拔掉电视电源不是同一件事。本次在应用中查到能使 WLED 继续收到颜色、或在失败启动后收到开灯请求的路径；没有在用户的电视上重现闪光，也没有证据把每一次闪光都归因于本应用。

## 审查依据

- 输入：干净的 `main@1a4d921`。以仅含 README 的根提交 `03dabc5` 比较当前整个源树，而非只审最后一次文档提交。生产范围含 `common`、`tv`、`mobile`；重点沿启动、投屏、采样心跳、TEST、写出、释放和状态回报追踪。比较范围不等于逐提交/逐行验收。
- 规范：[技术方案 §6.3](../design/architecture.md#63-停止屏障与恢复) 要求息屏释放，亮屏的静态画面则应维持最后一帧；测试边界沿用[已确认的公共接口](../archive/fixes/2026-11-17-completion-audit.md#3-用户已确认的公共测试边界)。
- 修复前的 [Sony 息屏/亮屏记录](../archive/verification/wled/real-device-2026-11-17/cap-1-screen-off-on.txt) 显示系统进入 `Asleep`、服务和投屏仍在，唤醒后继续采样。它是旧版本的行为证据，没有同时记录待机灯光和 WLED 状态，不能当作已关灯或本次修复后的验收。

## 缺陷与处置

| 级别 | 修复前的证据（`1a4d921`） | 处置与边界 |
|---|---|---|
| P1 | `WledScreenService.java:167–182,312–333`：无新图像时每秒重发旧帧；默认显示变化仅更新 HDR/尺寸，系统息屏无停止入口。 | 系统息屏/关机和默认显示变化接入 `CaptureSession` 的停止屏障。非交互启动不获取投屏、不请求开灯；亮屏事件不重启旧会话。亮屏且收到首个实际样本后仍保留静态心跳。 |
| P1 | `WledScreenService.java:373–395,418–432,820–823` 和 `TestPatternActivity.java:149–162`：独立线程请求 `on:true`，早于真实帧，采集甚至早于虚拟显示成功。若启动失败或与停止重叠，这个请求不受帧写线程约束。 | CAPTURE 与十秒 TEST 共用 `WledFrameSink`，按本次配置的目标与通道在同一 writer 上处理首帧开灯、颜色与释放；不重试不确定的开灯请求。已出进程的报文仍不能撤回。 |
| P1 | `TestPatternActivity.java` 仅在 `onDestroy()` 取消；离开页面却未销毁时，测试还可继续驱动灯带。 | 收到息屏信号或在 `onStop()` 时取消测试、停 ticker、报告释放结果并归还租约；回到原页面或恢复旧实例不会自行发起下一轮。 |
| P1 | `LedStreamer.stop()` 限制的是调用者等待时间，而旧服务/TEST 页超时后立即关闭连接并归还租约。旧 writer 仍可能在完成关灯，下一所有者已能开灯。 | UI 仍按时报告 `UNCONFIRMED`。已启动的 writer 在最后一次本地 I/O 完成后才关闭固定连接、归还固定 epoch；未启动的失败路径立即清理。 |
| P2 | `LayoutProbeSender.java:144,161`：TV 布局探针先请求开灯，停止时只发黑帧。回环测试捕获到最后的 HTTP 写入仍是 `{"on":true}`；黑帧无法证明设备已关。 | 同一个探针线程停止白色输出、发黑、请求关灯，若请求成功再读回，最后才归还租约。停止信号只唤醒等待，不中断正在执行的关灯操作；布局页只显示探针已停，不显示硬件已关。 |
| P2 | `WledHttpClient.readStateBlocking()` 在 `/json/state` 含 `live` 时跳过 `/json/info`。两个响应矛盾时可将仍在 realtime 的设备报告为已释放。 | 在同一次有时限的 `readState` 内读取 `/json/state.on` 和 `/json/info.live`。只有有效读回二者均为 `false`，且未超时，采集/十秒测试才能报告释放已确认。 |
| P2 | `WledScreenService` 同时接入 `LedStreamer` 与可发黑帧的 `WledSession`，同一次停止实际发送两帧终止黑，而不是约定的一帧。 | 采集由 writer 独占终止黑帧，`WledSession.forCaptureWriter` 只负责设备控制；独立使用的会话仍可自行发送黑帧。组合接口测试直接统计实际发送次数。 |

## 本地验收与未关闭项

- [可复核的原始 RED 摘录](evidence/2026-11-18-tv-standby.txt)分别覆盖待机启动、开灯与停止交错、探针最后一次写入、矛盾读回和双黑帧。持有输出权直到旧 writer 完成的测试另列编译 RED，不冒充行为失败。HTTP/UDP 测试只使用本机回环，不访问电视或灯带。
- 离线 Gradle 强制重跑：`common:testDebugUnitTest` 241 项、`mobile:testDebugUnitTest` 1 项，均通过；`tv:testDebugUnitTest` 无 JVM 测试源。三个模块 debug lint 均为 0 error，仍有 common 71、mobile 6、tv 55 个 warning，不视为已清零。mobile/TV debug、未签名 release 及三个模块的 debug AndroidTest APK 均已构建；未执行设备测试。
- 规范复核区分了三类证据：息屏/电源回调接线和前后台生命周期经源码检查，单写线程/终止帧/互斥经 JVM 与回环验证，遥控器待机后的物理灯态仍待下节验收。旧 Sony 观察只保留一份，不再用作当前通过记录。
- 独立的产品差距：共享十秒测试页目前固定启动四边色（`SIDES`），[技术方案 §9.2](../design/architecture.md#92-预览与图案)所列行走/纯色尚无选择入口，不属于本次待机修复。项目其余代码未逐行或逐设备签收。

## 真机验收方法（未执行）

1. 在同一构建、同一电视和控制器上记录版本，排除第二个发送端。启动采集并停在带明显颜色的静态菜单；应持续保持颜色，不能用“没有新帧”判成息屏。
2. 按遥控器待机而非切换 HDMI。对照系统睡眠时刻、服务停止原因、终止的投屏、最后的彩色 UDP、黑帧与关灯请求，以及 `/json/state.on` 和 `/json/info.live` 的独立读回。等待超过**该设备实际配置的** realtime timeout，再观察灯带，不能只拍停止瞬间。
3. 唤醒后不进行操作：不应出现旧会话重新开灯或发送颜色；显式重新开始时才建立新会话。另测快速待机/唤醒、测试图案页退后台和控制器断网；读回失败只能报告未确认。
4. 单独记录电视直接断电、WLED 自身重启、其他发送端或同步预设。Android 未获得执行时间时不能保证发送黑帧或 HTTP off；这些情况不能由 JVM 测试代验。
